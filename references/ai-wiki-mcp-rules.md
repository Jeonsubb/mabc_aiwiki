# ai-wiki MCP 규칙 (이번 세션 수정 반영)

## 목적
- ai-wiki 스킬이 MCP 위키 제안(add/change) 흐름에 맞게 수정됐음을 다음 세션에서도 빠르게 확인한다.
- 규칙 근육을 기억에 남기지 않고 스킬/참고 파일에 고정한다.

## 핵심 흐름
1. 원본 대화는 MCP 도구 `submit_conversation`으로 저장한다.
2. 위키 제안은 MCP 도구 `create_proposal`로 만든다.
3. 제안은 `pending` 상태로만 저장하고, 승인·기각·위키 직접 변경은 MCP 도구에서 하지 않는다.

## content 규칙
- `content`에는 다음만 사용한다:
  - `title`
  - `summary`
  - `body`
  - `tags`
  - `related`
- 다음 키는 `content`에 넣지 않고 별도 인자로만 전달한다:
  - `rationale`
  - `target_node_id`
- 허용되지 않은 키가 `content`에 들어오면 생성 단계에서 오류로 차단된다.
- 승인 단계에서도 `content` 키를 다시 검증하며, 잘못된 키가 있으면 승인되지 않는다.

## change 규칙
- `change` 제안은 실제 대상 위키 `node_id`가 있을 때만 만든다.
- 없는 ID로는 생성 단계에서 막힌다.
- 승인 시에도 대상 위키 존재 여부를 검사해, 없으면 승인되지 않는다.

## 작성 원칙
- 원본 대화의 사용자 발언과 AI 답변 모두 정리하되, 발화자를 구분한다.
- AI 제안을 사용자 결정이나 검증된 사실로 취급하지 않는다.
- 원문에 없는 사실·전망은 넣지 않는다. 필요하면 추론이라고 표시한다.
- 시나리오·예측은 확정적 사실처럼 쓰지 않는다.
- 한글 문서에 불필요한 영어나 한자를 섞지 않는다.
- 위키 본문에는 작성 지침·처리 절차를 그대로 넣지 않는다. content는 주제 내용만 담는다.
- rationale에는 판단 이유만 간결하게 적고, 절차 설명을 반복하지 않는다.

## 저장소/파일 규칙
- 결과물을 직접 `wiki/`에 쓰지 않고, MCP 도구로 pending 제안까지만 저장한다.
- 등록본 스킬 파일과 프로젝트 원본 스킬 파일은 동일하게 유지해야 한다.
- 불일치는 `diff`로 확인한다.

## 변경 확인 포인트
- 등록본 경로: `skills/mcp/ai-wiki/SKILL.md`
- 원본 경로: 프로젝트 루트의 `ai-wiki-SKILL.md`
- 최종 확인은 `skill_view(name="ai-wiki")`로 한다.

## 이번 세션에 넣은 문구 예시
- 처리 절차 2번:
  - "원본 대화의 사용자 발언과 AI 답변 모두 정리하되, 발화자를 구분한다. AI 제안을 사용자 결정이나 검증된 사실로 취급하지 않는다. 원문에 없는 사실·전망은 넣지 않고, 필요하면 추론이라고 표시한다."
- 처리 절차 3번 끝에 추가:
  - "정리할 만한 새 정보가 없으면 새 제안을 만들지 않아도 된다."
- 예외 처리:
  - "MCP 조회·제안 저장 중 문제가 생기면 어디서 막혔는지 명확히 알린다."
  - "정리할 만한 새 정보가 없으면 새 입력을 따로 제안하지 않아도 된다."
- 호출 예시:
  - "원본 대화 텍스트 또는 제출용 대화 ID"
  - "기존 위키/제안 조회 결과 (이미 있으면)"
  - "필요하면 추가 제안 전에 MCP로 검색·제안 목록부터 확인할 것"
