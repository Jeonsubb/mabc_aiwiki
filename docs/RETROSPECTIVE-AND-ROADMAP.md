# Nodus 회고와 로드맵 (2026-09-25)

## 1. 한 줄 요약

AI 대화를 승인 통제형 개인 위키와 생각 지도로 바꾸는 서비스. 사용자가 에이전트에 "위키에 저장해"라고 말하면 MCP로 원문이 들어오고, Solar Pro 4가 예선 스킬 ai-wiki의 규칙으로 신규·갱신·연결 제안을 만들며, 사용자가 수락한 것만 위키와 생각 지도에 반영된다.

## 3. 만든 것

### 서비스 구조

- Frontend: React · Vite · three.js, Vercel 배포. `/api`는 Vercel 프록시로 Render 백엔드에 전달한다.
- Backend: Node.js · Express · TypeScript, Render 배포. Prisma로 PostgreSQL을 다룬다.
- MCP 서버: `/mcp` 경로에 Streamable HTTP로 마운트. 사용자별 Bearer 토큰으로 인증하고 `submit_conversation`으로 대화 원문을 받는다.
- LLM: Solar Pro 4 단일 사용. `docs/ai-wiki-SKILL.md` 전체를 시스템 지침으로 로드한다.

### 핵심 흐름 (PRD 5단계)

1. 대화 보관: 사용자가 요청한 대화 구간만 원문 그대로 보관한다. 요청 없이는 수집하지 않는다.
2. 후보 생성: Solar Pro 4가 기존 위키와 대조해 신규 노드·갱신·연결 후보를 만든다. 같은 주제가 있으면 갱신을 우선한다.
3. 제안 제시: 제안 이유, 원문 근거 세그먼트, 변경 전·후 미리보기를 붙인다. 연결 제안에는 관계 유형과 판단 근거가 있어야 하며 공통 단어만으로는 연결하지 않는다.
4. 사용자 확인: 수락 또는 기각. 이미 결정된 제안은 다시 결정할 수 없고, 기준 버전이 달라지면 갱신을 중단한다.
5. 위키 반영: 위키 노드·버전 이력·관계를 한 트랜잭션으로 저장하고, 승인된 노드와 관계만 생각 지도에 그린다.

### 예선 스킬이 서비스에 들어간 방식

| 스킬 규칙 | 구현 |
|---|---|
| 원문과 정리본 분리, 원문에 없는 내용 금지 | 유입 기록(Record)과 위키 노드(WikiNode) 테이블 분리, 제안별 근거 세그먼트 연결 |
| 제안만 생성, 위키에 직접 쓰기 금지 | Proposal 테이블과 별도 승인 라우트. MCP 도구로는 승인 불가 |
| 병합·분리·연결 판단 | 제안 유형 추가·갱신·분리·병합·연결·보강·수정 |
| 민감정보 경고 | 생성 결과에 민감정보 플래그 반환 |

## 4. 현재 상태와 알려진 문제

- 배포본은 공용 데모 계정으로 자동 로그인된다. 심사용 구조라 실사용자 데이터가 없다.
- 배포 DB는 마이그레이션 폴더 없이 db push로 관리해 왔고, 시연 준비 과정에서 여러 번 초기화됐다.
- CI의 mcp-check 잡은 러너에 uv가 없을 때 uv.lock을 요구하는데, .gitignore가 uv.lock을 금지해 서로 모순된다. 이 때문에 main CI가 계속 실패 상태다.
- `session-graph/` 폴더의 AutoSchemaKG 기반 세션 그래프 엔진은 파이썬 워커 구조라 Render의 Node 서비스와 연결되지 않았다. 경로 상수를 함수로 바꾼 뒤 옛 방식으로 쓰는 곳이 남아 첫 수집이 실패한다.
- 대화방(챗봇) 기능은 제출 직전에 화면에서 제거됐다. 서버 라우트와 도구 호출 코드는 남아 있다(아래 5절).
- 생각 지도 배경 이미지(`client/public/milky-way.avif`)의 출처가 저장소에 기록되어 있지 않다.

## 5. 이 브랜치에 함께 올린 미완성 작업

- `server/src/services/chatTools.ts`, `server/src/solar.ts`, `server/src/routes/chats.ts`: 서비스 내 대화에서 Solar가 `search_wiki`, `search_chats`, 제안 생성 도구를 호출하는 도구 호출 루프. 최대 3회 왕복. 화면에서는 대화방이 빠져 있어 현재 사용자에게 노출되지 않는다.
- `docs/PRD-Nodus.*`, `docs/poster-nodus.*`, `docs/make_*_pptx.py`, `docs/arch-icons/`, `docs/poster-assets/`: 결선 제출용 PRD와 포스터의 HTML 원본, PDF, 생성 스크립트, 아이콘, 화면 캡처.

## 6. 앞으로의 방향

### 포지셔닝

Claude·ChatGPT의 메모리와 같은 자리에서 경쟁하지 않는다. 그 메모리들은 한 서비스 안에서만 작동하고, 무엇이 저장됐는지 사용자가 보거나 되돌릴 수 없으며, 사실을 기억하지 지식을 구조화하지 않는다. Nodus는 여러 AI 대화에서 나온 지식을 사용자가 소유하고 통제하는 계층이다. 메모리와 경쟁하는 것이 아니라 메모리가 흘려보내는 것을 받는 층으로 자리 잡는다.

### 우선순위

1. 마찰 없는 수집. 지금은 "저장해"라고 말해야 하고 MCP 설정도 어렵다. 각 AI 서비스의 대화 내보내기 파일을 통째로 가져오는 기능을 먼저 만들고, 그다음 브라우저 확장으로 대화창에서 한 번에 보내기를 붙인다. 이것이 없으면 다른 기능은 쓰이지 않는다.
2. 반대 방향 흐름. 위키를 다시 AI에게 꺼내 주는 MCP 읽기 도구(`search_wiki`, `get_node`)를 에이전트가 대화 중에 부르게 한다. "내가 승인한 지식만 AI가 참고한다"는 메모리와 정반대의 가치가 생기고, 읽기 도구는 이미 있어서 비용이 가장 적다.
3. 범위 밖으로 뺐던 것 중 실제로 요구되는 것만 복귀. 제안 직접 편집이 첫 번째다. 세션 그래프 엔진은 파이썬 워커를 서버와 같은 곳에서 돌릴 수 있게 구조를 바꾼 뒤에 붙인다.
4. 시간축. 주간 리캡(새로 생긴 노드, 갱신된 결정, 새 연결)은 데이터가 쌓인 뒤에 의미가 있으므로 1·2번 다음이다.

### 먼저 검증할 가설

"AI를 두 개 이상 쓰는 사람이 실제로 지식이 흩어져서 고통을 느끼는가." 한 AI만 쓰는 사람은 그 서비스의 메모리로 충분하다고 느낄 가능성이 크다. 대화 내보내기 가져오기만 만든 뒤 다중 AI 사용자 다섯 명에게 자기 대화 100건을 넣게 하고, 일주일 뒤 다시 열어보는지 관찰한다. 효과는 가설이며 수치 없이 주장하지 않는다.

### 제품화 전에 정리할 기술 부채

- Prisma 마이그레이션 폴더를 만들고 배포 DB를 초기화 없이 운영한다.
- CI의 uv.lock 조건을 고치고 `.pyc` 추적을 막는다.
- session-graph의 경로 함수 오용 15곳을 수정하고, 워커 배포처를 정한다.
- 배경 이미지의 출처와 라이선스를 기록하거나 자유 라이선스 이미지로 교체한다.
- 데모 자동 로그인을 실제 회원 가입·로그인으로 되돌린다.
